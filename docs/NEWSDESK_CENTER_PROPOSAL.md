# 뉴스데스크 센터 (NewsDesk Center) - 프로젝트 기획서

> 작성일: 2026-02-14
> 상태: 기획 단계

---

## 1. 프로젝트 개요

### 1.1 한 줄 요약
AI 에이전트 파이프라인 기반의 독립형 뉴스 인텔리전스 플랫폼.

### 1.2 배경
현재 **펀드팀 메신저** 내에 "뉴스데스크"라는 일일 시장 브리핑 기능이 내장되어 있다. 이 기능은 네이버/yfinance에서 뉴스를 수집하고, GPT-5-mini가 단일 API 호출로 칼럼·뉴스카드·감성분석·주목종목을 한꺼번에 생성하는 구조다.

그러나 이 방식에는 근본적 한계가 있다:

| 현재 한계 | 설명 |
|-----------|------|
| **단일 호출 병목** | 11개 JSON 필드를 한 번에 생성 → 뒤쪽 항목 품질 저하 (-26%) |
| **키워드 기반 수집** | 사전 정의된 키워드로만 검색 → 예상치 못한 이슈 누락 |
| **클러스터링 부재** | 같은 사건의 10개 기사가 개별 뉴스로 취급됨 |
| **인사이트 깊이** | 뉴스 텍스트만 분석, 실제 시세/차트 데이터와 연결 안 됨 |
| **시각화 한계** | 뉴스 간 인과관계, 파급 경로를 보여줄 수 없음 |
| **확장성** | 펀드메신저에 종속, 독립 서비스로 제공 불가 |

### 1.3 비전
뉴스데스크를 펀드메신저에서 **추출(extract)** 하여 독립 프로젝트 **"뉴스데스크 센터"** 로 만든다. 핵심은 **4단계 AI 에이전트 파이프라인**으로, 각 단계가 전문 에이전트로 분리되어 더 깊은 분석을 수행한다.

최종적으로 뉴스데스크 센터는 **AI 트레이딩 시그널 시스템**과 통합되어, 뉴스 기반 매매 신호를 자동 생성하는 SaaS로 확장할 수 있다.

## 2. 현재 시스템 분석 (AS-IS)

### 2.1 현재 아키텍처
```
네이버 API ──┐
             ├─→ RawNews DB ─→ [단일 GPT 호출] ─→ NewsDesk JSON ─→ React UI
yfinance ────┘
```

### 2.2 현재 데이터 흐름
1. **수집**: 14카테고리 키워드로 네이버 검색 + 8개 해외 티커 yfinance
2. **저장**: RawNews 테이블 (title, description, link, pub_date)
3. **분석**: 단일 GPT-5-mini 호출 (200줄 시스템 프롬프트, 최대 50개 뉴스 입력)
4. **출력**: JSON (칼럼2, 카드6, 키워드8-12, 감성, 주목종목3)
5. **표시**: React 페이지 (마크다운 렌더링, 키워드 버블, 벤치마크 차트)

### 2.3 현재 수치
- 일일 수집: 100-150개 뉴스
- AI 호출: 1회/일 (GPT-5-mini, ~32K 출력 토큰)
- 비용: ~$0.08/일
- 생성 시간: ~30-60초
- 품질: 칼럼 83%, 카드 82%, 종목 84% (목표 대비 달성률)

### 3.2 Stage 1: 크롤링 에이전트

**역할**: 다양한 소스에서 뉴스를 광범위하게 수집

#### 현재 → 개선
| 항목 | 현재 | 뉴스데스크 센터 |
|------|------|-----------------|
| 국내 소스 | 네이버 검색 API만 | 네이버 + 다음 + 구글뉴스 + RSS |
| 해외 소스 | yfinance 8개 티커 | Bloomberg, Reuters, CNBC, WSJ RSS |
| 수집 방식 | 사전 키워드 14카테고리 | 키워드 + 트렌딩 토픽 자동 탐지 |
| 수집량 | 100-150개/일 | 500-1000개/일 |
| 수집 주기 | 1일 1회 (05:30) | 실시간 (15분 간격) |
| 본문 수집 | 제목+요약만 | 전문 스크래핑 (가능한 경우) |

#### 데이터 모델 확장
```
RawNews (확장):
  - id
  - source (naver, daum, google, bloomberg, reuters, rss)
  - title
  - description
  - full_content (본문 전문 - 신규)
  - link
  - pub_date
  - language (ko, en)
  - author
  - media_name (매체명 - 신규)
  - image_url
  - collected_at
  - newsdesk_date
  - processing_status (raw, clustered, analyzed - 신규)
```

### 3.3 Stage 2: 클러스터링 에이전트

**역할**: 수집된 뉴스를 사전 정의 없이 자동으로 주제별로 묶음

#### 핵심 설계: 비지도(Unsupervised) 클러스터링
현재 시스템은 14개 키워드 카테고리로 뉴스를 분류하지만, 이는 "미리 정의한 토픽"에만 반응한다. 뉴스데스크 센터는 **주제를 사전에 정의하지 않고**, AI가 자동으로 뉴스 간 유사성을 판단하여 클러스터를 형성한다.

#### 클러스터링 방식
```
500개 뉴스 입력
  ↓
[임베딩 생성] (OpenAI text-embedding 또는 sentence-transformers)
  ↓
[유사도 기반 클러스터링] (HDBSCAN / 계층적 클러스터링)
  ↓
결과: 15-30개 뉴스 클러스터
  - 클러스터 1: "삼성전자 HBM 수주" (기사 12개)
  - 클러스터 2: "FOMC 금리 동결" (기사 8개)
  - 클러스터 3: "테슬라 자율주행 사고" (기사 5개)
  - ...
  - 노이즈: 어디에도 속하지 않는 단독 기사들
```

#### 클러스터별 처리
- **대표 기사 선정**: 클러스터 중심(centroid)에 가장 가까운 기사
- **클러스터 제목 자동 생성**: AI가 묶인 기사들을 읽고 대표 제목 생성
- **시간축 정렬**: 같은 클러스터 내 기사를 시간순으로 배치 → 사건 전개 파악
- **중요도 점수**: 기사 수 + 매체 다양성 + 시간 분포로 중요도 산출

#### 데이터 모델
```
NewsCluster:
  - id
  - newsdesk_date
  - cluster_label (AI가 생성한 대표 제목)
  - news_ids (소속 뉴스 ID 목록)
  - representative_news_id (대표 기사)
  - importance_score (중요도 0-100)
  - news_count (기사 수)
  - time_span_hours (첫 기사~마지막 기사 시간 차)
  - centroid_embedding (클러스터 중심 벡터)
  - created_at
```

### 3.4 Stage 3: 인사이트 추출 에이전트

**역할**: 클러스터별로 심층 분석 + 시세 데이터 연계

#### 현재와의 차이
현재 시스템은 뉴스 텍스트만으로 분석한다. 뉴스데스크 센터는 **시세 데이터를 함께 입력**하여 "뉴스가 실제 시장에 어떤 영향을 미쳤는가"를 분석한다.

#### 클러스터별 인사이트 생성
```
클러스터 "삼성전자 HBM 수주" (기사 12개)
  +
Yahoo Finance 차트 데이터:
  - 삼성전자 1주일 가격/거래량
  - SK하이닉스 1주일 가격/거래량
  - NVIDIA 1주일 가격/거래량
  - SOX 반도체 지수
  ↓
[인사이트 에이전트 (GPT)]
  ↓
출력:
  1. AI 재작성 기사 (클러스터 기반 종합 기사)
  2. 관련 종목 영향 분석 (실제 차트 데이터 인용)
  3. 인과관계 추론 (이 뉴스 → 어떤 시장 반응)
  4. 연결 클러스터 식별 (이 클러스터와 관련된 다른 클러스터)
```

#### AI 재작성 기사
현재 시스템의 "뉴스카드"는 개별 뉴스를 정리한 것이다. 뉴스데스크 센터의 AI 재작성 기사는 **클러스터 내 여러 뉴스를 종합하여 하나의 새로운 기사**를 작성한다.

```
입력: 12개 기사 (삼성전자 HBM 관련)
  - "삼성전자 HBM3E 양산 본격화" (한경)
  - "엔비디아, 삼성 HBM 테스트 통과" (매경)
  - "SK하이닉스 독점 깨질까" (서울경제)
  - ... 9개 추가

출력: 1개 종합 기사
  "삼성전자의 HBM3E가 엔비디아 품질 테스트를 통과하면서..."
  (12개 기사의 핵심을 하나의 서사로 엮은 기사)
```

#### 데이터 모델
```
ClusterInsight:
  - id
  - cluster_id (FK)
  - synthesized_article (AI 재작성 종합 기사)
  - related_tickers (관련 종목 목록)
  - market_impact (시장 영향 분석)
  - causality_links (인과관계 - Stage 4 시각화용)
    [{"from_cluster_id": 1, "to_cluster_id": 5, "relation": "원인→결과"}]
  - sentiment_score (0-100)
  - price_data_snapshot (분석 시점의 시세 데이터)
  - created_at
```

### 3.5 Stage 4: 시각화 에이전트 (React Flow 마인드맵)

**역할**: 뉴스 클러스터 간 인과관계를 시각적 마인드맵으로 표현

#### React Flow 마인드맵
```
[FOMC 금리 동결] ──원인──▶ [달러 약세] ──결과──▶ [원/달러 하락]
                                                      │
                                                 영향
                                                      ▼
                                              [수출주 약세]
                                                      │
                                                 관련
                                                      ▼
[삼성전자 HBM 수주] ──────────────────────────▶ [반도체 섹터 반등]
```

각 노드는 하나의 **뉴스 클러스터**이고, 엣지는 **인과관계**를 나타낸다.

#### 노드 디자인
- **크기**: 중요도 점수에 비례
- **색상**: 감성 (초록=긍정, 빨강=부정, 회색=중립)
- **아이콘**: 카테고리별 (금융, 테크, 에너지 등)
- **클릭**: AI 재작성 기사 + 원본 뉴스 목록 + 차트 데이터 표시
- **호버**: 요약 + 기사 수 + 관련 종목

#### 엣지 디자인
- **방향**: 화살표 (원인 → 결과)
- **두께**: 관련 강도에 비례
- **라벨**: 관계 유형 (원인, 결과, 관련, 영향, 반작용)

#### 인터랙션
- **줌/패닝**: 전체 맵 탐색
- **노드 클릭**: 사이드패널에 상세 정보
- **시간 슬라이더**: 시간대별로 뉴스 전개 과정 애니메이션
- **필터**: 카테고리/감성/중요도별 필터링

## 4. 펀드메신저와의 연동

### 4.1 연동 방식
뉴스데스크 센터는 독립 프로젝트이지만, 펀드메신저에 API로 데이터를 제공한다.

```
[뉴스데스크 센터] ──API──▶ [펀드메신저]
                              │
                         기존 뉴스데스크 UI를
                         센터 API로 데이터 소스 전환
```

### 4.2 API 설계 (제공)
```
GET  /api/v1/briefing/today         → 오늘의 브리핑 (기존 호환)
GET  /api/v1/briefing/{date}        → 특정 날짜 브리핑
GET  /api/v1/clusters/{date}        → 클러스터 목록
GET  /api/v1/clusters/{id}/insight  → 클러스터 인사이트
GET  /api/v1/mindmap/{date}         → 마인드맵 데이터 (React Flow용)
GET  /api/v1/sentiment/{date}       → 감성 지표
GET  /api/v1/trending               → 실시간 트렌딩 클러스터
```

### 4.3 하위 호환
펀드메신저의 기존 뉴스데스크 UI는 그대로 유지하되, 데이터 소스를 뉴스데스크 센터 API로 전환한다. 기존 JSON 구조(columns, news_cards, keywords, sentiment, top_stocks)를 센터가 생성하여 호환성 유지.

## 5. AI 트레이딩 시그널 통합 (장기 비전)

### 5.1 개요
뉴스데스크 센터의 최종 목표는 **뉴스 인텔리전스 → 매매 시그널** 자동화다.

```
뉴스 클러스터 + 인사이트 + 시세 데이터
  ↓
[트레이딩 시그널 에이전트]
  ↓
매매 시그널: "삼성전자 매수 신호 (신뢰도 72%)"
  - 근거: HBM 수주 확대 (클러스터 #3)
  - 차트: 지지선 돌파 + 거래량 증가
  - 리스크: FOMC 불확실성 (클러스터 #7)
```

### 5.2 시그널 유형
| 시그널 | 트리거 | 예시 |
|--------|--------|------|
| 뉴스 기반 매수 | 긍정 클러스터 + 차트 지지 | "NVIDIA 실적 호조 + 기술적 돌파" |
| 뉴스 기반 매도 | 부정 클러스터 + 차트 약세 | "규제 강화 + 하락 추세" |
| 이벤트 알림 | 고중요도 클러스터 발생 | "긴급: FOMC 서프라이즈" |
| 섹터 로테이션 | 클러스터 감성 변화 패턴 | "에너지→테크 자금 이동 감지" |
| 리스크 경고 | 공포 지수 급등 | "시장 공포 지수 80+ 돌파" |

### 5.3 암호화폐 확장
LLM 기반 암호화폐 트레이딩 시그널 SaaS:
- 크립토 전용 뉴스 크롤링 (CoinDesk, CoinTelegraph, 온체인 데이터)
- 소셜 미디어 감성 분석 (X/Twitter, Reddit)
- 온체인 지표 연동 (고래 이동, 거래소 입출금)
- 실시간 시그널 발송 (Telegram/Discord 봇)

## 부록: 펀드메신저 뉴스데스크의 AI 프롬프트 최적화 이력

뉴스데스크 센터 개발 시 참고할 수 있는, 현재 시스템에서의 프롬프트 엔지니어링 경험:

| 이터레이션 | API | 핵심 변경 | 칼럼 | 카드 | 종목 |
|-----------|-----|----------|------|------|------|
| Iter 0 | Chat Completions | 기본 프롬프트 | 64% | 71% | 82% |
| Iter 1 | Chat Completions | XML 구조 + 밀도 지시 | 74% | 77% | 69% (퇴행) |
| Iter 2 | Responses API | verbosity=high | 79% | 82% | 84% |
| Iter 3 | Responses API | 프롬프트 세부 조정 | 퇴행 → 복원 |
| Iter 4 | Responses API | max_tokens=32K + reasoning=medium + 문단수 목표 + Few-shot | 최종 |

**핵심 교훈** (센터 개발 시 반영):
1. **verbosity 파라미터**가 출력 길이에 가장 큰 영향 (Responses API 전용)
2. **글자수 목표는 LLM이 못 지킴** → 문단/문장 수 목표가 효과적
3. **데이터 전처리 > 프롬프트 지시** (특히 소형 모델)
4. **단일 호출 11개 항목 → 뒤쪽 품질 저하** (이것이 센터에서 분리 호출하는 이유)
5. **Few-shot 예시가 길이 변동성 감소에 가장 효과적**
6. **오버슈트 전략은 역효과 가능** (목표의 1.3배 이상 요구 시 품질 저하)
