## 1. 프로젝트 비전

### 1.1 한 줄 요약
전국 50개 대학교 투자동아리를 연결하는 **투자 커뮤니티 플랫폼** + **AI 투자 인텔리전스 서비스**.

### 1.2 현재 → 목표

| 항목 | 현재 (2026.02) | 목표 |
|------|---------------|------|
| **사용자** | 1개 팀, 5~10명 | 50개 대학, **1,500~2,000명** |
| **서비스** | 팀 내 매매관리 도구 | 팀 간 정보교환 커뮤니티 |
| **AI** | OpenAI API 일 3회 제한 | **자체 AI 서버, 제한 없는 AI 서비스** |
| **뉴스데스크** | 로컬 수작업 업로드 | **24시간 자동 운영 서비스** |
| **데이터** | 단순 기록 | 매매 패턴 분석 + 종목 추천 + **자체 투자모델 학습** |
| **수익 모델** | 없음 | 구독제 + 크레딧 마켓 |
| **백엔드** | FastAPI (Python) | Spring Boot (Java) — 마이그레이션 진행 중 |

| 항목 | 비용 | 비고 |

## 5. GPU 서버 상세 분석

### 5.1 gpt-oss-120b 구동 요구사항

OpenAI가 2025년 8월 공개한 오픈소스 모델.

| 항목 | 사양 |
|------|------|
| 총 파라미터 | 117B (120B급) |
| 활성 파라미터 | **5.1B** (MoE 아키텍처) |
| 양자화 | MXFP4 (240GB → 80GB) |
| 라이선스 | **Apache 2.0** (상업적 이용 자유) |
| 최소 VRAM | 80GB (H100 1장) 또는 RTX 5090 × 2~3장 |
| 성능 | o4-mini 수준 (코딩, 추론, 수학) |

**MoE(Mixture-of-Experts)의 의미**:
- 117B 파라미터 중 요청마다 5.1B만 활성화
- 결과적으로 5B 모델 수준의 추론 속도에 120B 모델의 품질
- 메모리는 전체 파라미터를 올려야 하지만, 연산은 가벼움

### 5.2 소비자 GPU vs 데이터센터 GPU (H100) — 왜 H100을 사는가?

**결론: 추론(inference)만 하면 소비자 GPU가 압도적으로 유리. H100이 필요한 건 학습(training).**

| 구분 | 소비자 GPU (RTX 5090) | 데이터센터 GPU (H100) |
|------|---------------------|---------------------|
| **GPU 간 통신** | PCIe 5.0 (128 GB/s) | NVLink (900 GB/s) = **7배** |
| **VRAM** | 32GB GDDR7 | 80GB HBM3 |
| **메모리 대역폭** | 1,792 GB/s | 3,350 GB/s |
| **가격** | 520~680만원 | 4,000~5,000만원 = **8배** |
| **멀티 GPU 학습** | 2장까지만 효율적 | 8장 NVLink 스케일링 |
| **24/7 안정성** | 게이밍 등급, ECC 없음 | 서버 등급, ECC 메모리 |
| **추론 성능/$** | **★★★★★** | ★★☆☆☆ |
| **학습 성능** | ★★☆☆☆ | **★★★★★** |

**H100을 사는 이유 3가지:**
1. **대규모 모델 학습**: 수십~수백 GPU로 모델 학습 시 NVLink 필수. PCIe에서는 GPU 간 그래디언트 교환이 병목
2. **단일 GPU 대용량**: 80GB VRAM으로 70B+ 모델을 한 장에 올림
3. **엔터프라이즈 안정성**: 24/7 연속 가동, ECC 메모리, 장기 보증

**우리에겐 필요 없는 이유:**
- **추론만 함** (이미 만들어진 모델을 돌리는 것)
- 추론에서 vLLM은 **복제 병렬화**(각 GPU가 독립 인스턴스) 사용 → GPU 간 통신 없음 → NVLink 불필요
- RTX 5090 8장(~4,200만원) ≈ H100 1장(~4,500만원) 가격인데 **처리량 4배 이상**
- 소비자 GPU의 추론 가성비는 데이터센터 GPU의 **3~5배**

### 5.6 500명 동시 요청 처리 분석

**전제 조건:**
- 운용보고서 1건: 입력 ~3,000 토큰 + 출력 ~9,000 토큰
- 500명 동시 요청 → 총 출력: **4,500,000 토큰**
- 목표: 전체 500건을 **5분 이내** 완료 (대기열 방식)
- 필요 처리량: 4,500,000 ÷ 300초 = **15,000 tok/s**

#### 모델별 500 동시 요청 처리

| 구성 | 모델 | GPU | 처리량 | 500건 완료 |
|------|------|-----|--------|-----------|
| A | gpt-oss-120b × 2 인스턴스 | 4× RTX 5090 | ~8,000 tok/s | 9.4분 |
| **B** | **gpt-oss-120b × 4 인스턴스** | **8× RTX 5090** | **~16,000 tok/s** | **4.7분** ✅ |
| C | gpt-oss-120b × 6 인스턴스 | 12× RTX 5090 | ~24,000 tok/s | 3.1분 |
| D | 소형 7-8B × 4 복제 | 4× RTX 5090 | ~20,000 tok/s | 3.8분 ✅ |
| **E (추천)** | **하이브리드: 120B×2 + 8B×4** | **8× RTX 5090** | **~28,000 tok/s** | **2.7분** ✅ |

> **구성 E (하이브리드)**: 복잡한 AI 분석은 gpt-oss-120b, 대량 보고서 생성은 fine-tuned 7-8B 모델로 분리.
> 보고서 품질은 8B fine-tuned 모델로도 충분하며, 120B는 매매습관 분석/종목 인사이트 등 고품질 추론에 집중.

#### 사용자 체감 지연시간

vLLM 연속 배칭(continuous batching) 기준:
- 500 동시 요청 시 각 사용자에게는 토큰이 스트리밍됨
- 첫 토큰 수신: ~1~3초
- 전체 보고서 완료: 대기열 위치에 따라 2~5분
- **체감**: "로딩 중..." → 텍스트가 점진적으로 나타남 (ChatGPT와 동일한 UX)

### 7.2 AI 분석 서비스 설계

#### A. 매매습관 분석 (개인별)

```
입력: 사용자의 최근 3개월 매매 기록
분석:
  - 매매 스타일 분류 (모멘텀 / 가치투자 / 스윙 / 데이트레이딩)
  - 평균 보유 기간, 손절 타이밍, 익절 패턴
  - 승률, 평균 수익률, 최대 수익/손실
  - 시간대별 매매 패턴 (장 초반/중반/후반)
  - 섹터 편향 분석
  - 감정적 매매 패턴 (급등 추격매수, 패닉셀 등)

출력: 개인화된 매매습관 리포트 (LLM 생성)
```

```
[2단계: LLM 해설] (GPU)
  - 입력: 후보 종목 + 사용자 프로필 + 최근 뉴스
  - 출력: "당신의 매매 성향을 고려할 때, 이 종목은..."
```

#### C. 자체 투자모델 학습

```
Phase 1: Traditional ML (3~6개월 데이터 후)

  - 포지션 성과 예측 (Gradient Boosting)
  - 포트폴리오 리스크 분석 (수학적 최적화)
  - GPU 불필요, CPU 충분

Phase 2: Deep Learning (6~12개월 데이터 후)
  - 뉴스 임팩트 예측 (Transformer, 뉴스 → 주가 변동)
  - 사용자 행동 임베딩 (Neural CF)
  - 시계열 예측 (LSTM/Transformer)
  - GPU 필요: RTX 4090 1장 충분

Phase 3: LLM 파인튜닝 (12개월+ 데이터 후)
  - gpt-oss-20b를 매매 분석 특화로 LoRA 파인튜닝
  - 학습 데이터: 의사결정서 + 토론 + 매매 기록 + 결과
  - "이 종목을 이 가격에 매수한 이유는...의 성과는..."
  - GPU 필요: RTX 4090 × 4 (QLoRA로 20B 파인튜닝)
  - 학습 주기: 분기 1회 (데이터 축적 후)
```

### 7.3 법적/윤리적 고려사항

| 항목 | 요구사항 | 대응 |
|------|---------|------|
| 개인정보보호법 | 매매 데이터 = 개인정보 | 가입 시 데이터 분석 동의서 |
| 금융투자업 규제 | 투자 "추천"은 금융투자업 해당 가능 | "정보 제공" + "투자 판단은 본인 책임" 면책 |
| AI 투자 조언 | 자본시장법 제6조 | 투자일임/자문업 등록 or 면책 문구 필수 |
| 데이터 보관 | 개인정보 최소 수집 원칙 | 익명화/가명화 처리 후 학습 |
| 학생 데이터 | 미성년자 포함 가능 | 만 14세 이상 확인, 법정대리인 동의 |

**핵심**: "종목추천"이 아닌 **"매매습관 인사이트"**로 포지셔닝.
- "이 종목을 사라" (X) → 금융자문
- "당신은 모멘텀 투자 성향이며, 최근 손절이 늦은 패턴이 있습니다" (O) → 정보 제공

**한 줄 요약: GPU 서버는 직접 사서 코로케이션, 웹서버만 클라우드. 클라우드 GPU 임대 X.**

### 9.2 이 선택의 근거

| 이유 | 설명 |
|------|------|
| **500명 동시 처리** | 8× RTX 5090으로 500명 동시 보고서 요청 5분 내 완료 |
| **AI 품질 극대화** | gpt-oss-120b (o4-mini급) 무제한 사용, gpt-5-mini보다 상위 |
| **H100 불필요** | 추론만 하면 소비자 GPU가 가성비 3~5배. H100은 학습용 |
| **사용자 제한 해제** | AI 일 3회 → 무제한. 구독 가치 상승 |
| **자체 모델 학습** | 종목추천, 매매분석 — API로는 불가능한 차별화 |
| **뉴스데스크 24시간** | 추가 비용 0으로 상시 운영 |
| **데이터 주권** | 2,000명 매매 데이터가 외부 서버를 거치지 않음 |
| **스케일 불변** | 사용량 아무리 늘어도 추가 비용 없음 (API는 비례 증가) |

### 9.3 리스크 & 대응

| 리스크 | 대응 |
|--------|------|
| 하드웨어 고장 | 서버 2대 이중화 + API 자동 폴백 |
| RTX 5090 품귀/가격 | 물량 안정화 대기 또는 RTX 4090 중고로 초기 구성 후 교체 |
| 소비자 GPU 24/7 안정성 | 냉각 강화 + UPS + IDC 환경 (항온항습) |
| 사용자 폭증 (2,000명+) | GPU 추가 (슬롯 여유) 또는 클라우드 GPU 임시 확장 |
| 기술 인력 부족 | vLLM + Docker로 운영 자동화, 모니터링 대시보드 |

### 9.4 API를 완전히 버리지는 않는다

```
평시:  자체 GPU (gpt-oss-120b) → 100% 처리
장애:  OpenAI API 자동 폴백 → 서비스 무중단
피크:  자체 GPU 초과분 → API 오버플로우
특수:  GPT-5 급 필요 시 → API 호출 (극소량)
```

소량의 API 크레딧(월 5~10만원)을 유지하면 장애 대응 + 품질 보장.
